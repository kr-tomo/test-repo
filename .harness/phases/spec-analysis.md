# Phase 1: SPEC 분석

SPEC을 받으면 구현 전에 이 단계를 수행한다.

-----

## 수행 내용

SPEC으로부터 다음 세 가지를 추출한다.

**1. 테스트 가능한 요건**
검증 가능한 조건으로 재표현한 요건 목록.
“빠르게 동작해야 한다”처럼 측정 불가능한 표현은 구체화하거나 확인 항목으로 분류한다.

**2. 불명확한 부분**
해석이 둘 이상 가능한 항목. 가능한 해석을 함께 제시하고 판단을 요청한다.

**3. 모순 / 충돌**
요건 간 상충되는 내용. 어떤 요건끼리 충돌하는지 명시한다.

-----

## 출력 형식

```
## 추출된 요건

- [REQ-001] (요건 내용 — 검증 가능한 형태로 기술)
- [REQ-002] ...

## 확인 필요 항목

- [Q-001] (불명확한 내용)
  - 해석 A: ...
  - 해석 B: ...
  - → 어느 쪽으로 진행할지 확인 요청

## 모순 항목

- [C-001] REQ-001과 REQ-002 충돌
  - REQ-001: ...
  - REQ-002: ...
  - → 우선 적용할 요건 확인 요청
```

-----

## 규칙

- 질문은 이 단계에서 전부 한 번에 제시한다. 이후 단계에서 추가 질문으로 병목을 만들지 않는다
- 사용자 승인 후 Phase 2로 진행한다
- 승인 이후 요구사항 불명확성을 이유로 멈추는 경우는 SPEC 범위를 벗어난 결정이 필요한 경우에만 한정한다
