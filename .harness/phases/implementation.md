# Phase 3: 구현

SPEC과 TEST_DOC을 입력으로 테스트 코드와 구현 코드를 작성한다.

-----

## 순서

1. TEST_DOC의 케이스를 기준으로 테스트 코드를 먼저 작성한다
1. 테스트를 통과하는 구현 코드를 작성한다
1. 검증 루프 — 루프 포함 대상 전체 통과까지 반복한다

테스트 프레임워크와 실행 명령은 프로젝트에서 정한 바를 따른다.

-----

## 검증 루프

```
테스트 실행
    ↓
실패 원인 분석
    ↓
구현 수정
    ↓
재실행 → 전체 통과 시 종료
```

같은 방향으로 세 번 연속 실패하면 접근 자체를 재검토한다.

-----

## 루프 중 판단 기준

|상황                 |처리 방식               |
|-------------------|--------------------|
|명확한 버그, 해결책도 명확    |자체 해소 후 진행          |
|해결했으나 위험 요소 존재     |진행 + Report [D-N] 기록|
|선택지 여럿, 우열 불명확     |진행 + Report [D-N] 기록|
|SPEC 범위를 벗어나는 결정 필요|**중단 + 사용자 확인**     |

-----

## 변경 범위 원칙

- 요청된 범위 밖 코드를 수정하지 않는다
- 기존 코드에서 개선이 필요한 부분을 발견하면 건드리지 않고 Report에 언급한다
- 자신의 변경으로 인해 발생한 orphan(미사용 import, 변수 등)은 정리한다
