# Phase 4: 완료 Report

구현 완료 시 다음 구조로 리포트를 작성한다.

-----

## 리포트 형식

```
## 통과 현황

| TC | 레벨 | 루프 포함 | 결과 | 비고 |
|---|---|---|---|---|
| TC-001 | Unit | Yes | ✅ | |
| TC-002 | Component | Yes | ✅ | |
| TC-003 | Integration | No | — | 루프 미포함 |

## 판단 기록

### [D-001] (판단 제목)
- 상황: 어떤 상황이었는지
- 선택: 어떤 결정을 했는지
- 근거: 왜 그 선택을 했는지
- 잔여 위험: 남은 리스크 또는 모니터링 필요 항목

### [D-002] ...

## 미해결 항목

통과하지 못한 케이스가 있는 경우 사유와 권장 다음 단계를 기술한다.
없으면 이 섹션을 생략한다.

## 추가 관찰

구현 중 발견했으나 범위 밖이라 건드리지 않은 항목.
다음 작업 시 참고할 내용.
```

-----

## 규칙

- 판단 기록은 사용자가 나중에 검토할 수 있도록 충분히 구체적으로 작성한다
- “잘 됐습니다” 수준의 요약은 리포트가 아니다
- 루프 미포함 테스트(Contract, E2E 등)는 결과란에 `—`로 표기하고 비고에 사유를 명시한다
