# Phase 2: TEST_DOC 작성

Phase 1에서 승인된 요건을 바탕으로 테스트 케이스 문서를 작성한다.
테스트 레벨 정의 → `.harness/references/test-levels.md`

-----

## 테스트 레벨 선택 기준

개발 루프에 포함할 레벨은 프로젝트 수준에서 정의한다.
정의가 없으면 **Unit + Component**를 기본으로 한다.

Contract / E2E는 프로젝트 수준에 명시된 경우에만 TEST_DOC에 포함한다.
포함하더라도 개발 루프 실행 대상 여부는 별도로 표기한다.

-----

## 테스트 케이스 형식

```
### [TC-001] (케이스 이름)

- 레벨: Unit / Component / Integration / Contract / E2E
- 루프 포함: Yes / No
- 대상: (테스트할 함수 / 모듈 / 흐름)
- 조건: (사전 조건, mock 대상 등)
- 입력: (입력값 또는 요청)
- 기대 출력: (반환값, 상태 변화, 이벤트 등)
- 연결 요건: [REQ-001]
```

-----

## 작성 규칙

- 각 요건([REQ-N])에 대해 정상 케이스와 경계/예외 케이스를 모두 도출한다
- 테스트 케이스가 요건을 커버하지 못하는 경우 그 이유를 명시한다
- 구현 전에 작성 완료한다 — 구현 중에 케이스를 추가하지 않는다
  (구현 중 발견한 케이스는 Report에 기록하고 별도 논의한다)
