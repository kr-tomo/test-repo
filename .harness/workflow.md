# 작업 흐름

새 기능 구현 또는 변경 작업 시작 시 참조한다.

-----

## 전체 순서

```
SPEC 분석  →  TEST_DOC 작성  →  구현 + 테스트  →  완료 Report
 Phase 1        Phase 2            Phase 3           Phase 4
```

-----

## 단계 요약

|Phase      |입력      |출력             |관문        |
|-----------|--------|---------------|----------|
|1. SPEC 분석 |SPEC 문서 |요건 목록 + 불명확성 목록|**사용자 승인**|
|2. TEST_DOC|승인된 요건  |테스트 케이스 문서     |자동 진행     |
|3. 구현      |TEST_DOC|구현 코드 + 테스트 코드 |전체 통과     |
|4. Report  |구현 결과   |완료 리포트         |—         |

-----

## 관문 규칙

**Phase 1은 유일한 요구사항 확인 관문이다.**

- SPEC의 불명확성, 모순, 해석 분기는 모두 Phase 1에서 처리한다
- 사용자 승인 이후 단계에서 요구사항 불명확성을 이유로 멈추지 않는다
- Phase 3에서 SPEC 범위를 벗어나는 결정이 필요한 경우만 예외적으로 사용자에게 확인한다

-----

## 단계별 상세

각 단계의 수행 내용과 출력 형식은 `.harness/phases/` 참조.
