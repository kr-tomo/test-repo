# 테스트 레벨 정의

마틴 파울러의 MSA Test Pyramid 5단계 기준.

-----

## 레벨 정의

|레벨             |범위               |외부 의존 처리            |로컬 실행    |
|---------------|-----------------|--------------------|---------|
|**Unit**       |함수 / 클래스 단위      |없음                  |항상 가능    |
|**Component**  |서비스 내부 경계        |mock / stub 처리      |가능       |
|**Integration**|실제 DB / 외부 API 연동|실제 사용               |환경에 따라 다름|
|**Contract**   |서비스 간 계약 검증      |Pact broker 등 별도 인프라|별도 인프라 필요|
|**E2E**        |전체 시스템 end-to-end|실제 환경 전체            |로컬 불가    |

-----

## 피라미드 원칙

```
        [ E2E ]          ← 적게, 느리게, 비싸게
      [ Contract ]
    [ Integration ]
   [ Component   ]
  [ Unit         ]       ← 많이, 빠르게, 저렴하게
```

비용 대비 커버리지는 Unit / Component에서 가장 높다.
상위 레벨로 갈수록 실행 비용과 환경 의존성이 높아진다.

-----

## 개발 루프 포함 여부

Contract / E2E는 로컬 개발 루프에 포함하지 않는 것을 원칙으로 한다.
프로젝트에서 명시적으로 포함을 지정한 경우에만 루프에 편입한다.

Integration은 환경 구성(testcontainers 등)에 따라 포함 여부를 프로젝트에서 결정한다.

기본값 (CLAUDE.md에 정의 없는 경우): **Unit + Component**
